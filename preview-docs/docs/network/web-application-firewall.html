Web Application Firewall

SleakOps can put AWS WAF in front of each cluster's public load balancer, so malicious traffic is stopped before it reaches your applications. The firewall uses AWS managed rules for IP reputation, known bad inputs and the core rule set. It is off by default.

It applies to clusters created by SleakOps (not imported clusters) and only to the public load balancer.

Turn it on​

Only admins can change it.

  1. Open Providers → Accounts & Networking and select the account.
  2. In the Web application firewall card, click Manage.
  3. In the cluster's row, click Configure.
  4. Switch on Enable the web application firewall and click Enable.

The firewall starts in Count mode: requests are only counted and nothing is blocked. Review the matches for about a week, then switch the cluster to Block.

A cluster appears as unavailable when:

  • It is an imported cluster.
  • Its load balancer does not exist yet or is still being created.
  • The cluster is not ready yet.

Review false positives​

Check what the rules match before you block:

  • In your AWS account, open the AWS WAF console, select the web ACL sleakops-<cluster> and review the metrics per rule and the sampled requests.
  • To keep full request logs, switch on Keep full request logs for 30 days (Authorization and Cookie headers hidden) in the same form. The logs are in the CloudWatch Logs group aws-waf-logs-<cluster>, kept for 30 days. Switching it off deletes the log group and every log in it, so export the logs you need first.

A blocked request gets a 403 from the load balancer. If a specific rule blocks legitimate traffic, select it in Keep in count mode in the same form: it only records matches while the others keep blocking. Request bodies larger than 8 KB are never blocked by the body size rule.

Optional rule groups​

You can add more AWS managed rule groups, all off by default: anonymous IPs, SQL injection and Linux.

Allow or block IP addresses​

You can set two optional lists of IP addresses in the same form:

  • Always allow these IPs: requests from these addresses skip every other firewall rule, so the managed rules never count or block them either. Use it for your offices or trusted partners. It lets requests through in both Count and Block mode.
  • Always block these IPs: requests from these addresses are rejected in Block mode. In Count mode they are only recorded.

Enter one IP address or range per line, IPv4 or IPv6 (for example 203.0.113.7 or 198.51.100.0/24). Limits:

  • Up to 100 entries per list.
  • Ranges can be no wider than /16 for IPv4 or /32 for IPv6. Reserved ranges such as 127.0.0.0/8 are rejected.
  • The same range cannot be in both lists.
  • The block list cannot include the public IP your applications use for outbound traffic, because blocking it would cut their calls to your own load balancer.

Limit requests per IP address​

Switch on Limit requests per IP address and set how many requests one IP address can send in 5 minutes, between 10 and 2,000,000,000. In Block mode an address over the limit is rejected until its rate drops. In Count mode it is only recorded.

AWS usually reacts within about 30 seconds, so a burst can get through before the limit applies. Changing the limit resets the counters, and requests may go unlimited for up to a minute.

See the active rules​

The Active rules table in the cluster's form is read-only. It lists, in the order they are evaluated, each rule with its action and capacity (WCU). The first rule that allows or blocks a request decides; rules in Count only record.

Cost​

AWS bills the firewall in your account, not SleakOps. Reference prices for us-east-1:

  • USD 5 per month per web ACL.
  • USD 1 per month per rule group (USD 8 per month in total with the default rule groups).
  • USD 1 per month for each extra rule: the rate limit, and each allowed or blocked list that has IPv4 entries, IPv6 entries or both (up to two rules per list). They appear in Active rules.
  • USD 0.60 per million requests.

Logging adds CloudWatch Logs charges. Prices vary by region: see AWS WAF pricing.

Limits​

  • A load balancer can have only one web ACL. If your public load balancer already has a web ACL you attached yourself, SleakOps does not replace it and does not enable the firewall.
  • If one of your own Ingresses in the same ingress group sets an AWS WAF annotation, yours wins or the load balancer stops updating. Remove that annotation before you enable the firewall.
  • If the load balancer can't reach AWS WAF, by default it does not forward the request to your application, even in Count mode. To keep your applications online instead, select Let traffic through unfiltered under If AWS WAF is unavailable in the same form: requests then reach your application without protection until AWS WAF is back.

Turn it off​

Disabling the firewall removes the web ACL and its request logs. Deleting the cluster removes them too. If you enable it again, it starts from the default settings, in Count mode: set the mode, rule groups, IP lists, rate limit and logging again.
