# Configurá la red

Una vez que el stack de CloudFormation de una cuenta corrió, SleakOps necesita saber qué VPC, subnets y gateways usar antes de poder desplegar un clúster en ella. Este paso mapea esa red de AWS existente a los inputs que SleakOps requiere.

## Encontrá cuentas pendientes de configuración de red

Si tenés cuentas todavía esperando su configuración de red, vas a ver una alerta para eso en la lista de Providers. El banner dice **Network configuration pending** y nombra al provider con cuentas pendientes. Su botón **Configure networking** te lleva directo al formulario de configuración de red de esa cuenta en **Accounts & Networking**. Solo los admins ven esta alerta.

## Seleccioná la VPC

El panel de detalle de la cuenta abre con un único campo obligatorio: **VPC**. El dropdown lista cada VPC que SleakOps descubrió en la cuenta, como `<nombre o id> · <cidr_block>`.

<Zoom overlayBgColorEnd="rgba(255, 255, 255, 0.8)">
  <img
    src={require("./network-configuration/network-config-vpc.png").default}
    alt="Formulario de configuración de red con el dropdown de VPC sin seleccionar todavía"

</Zoom>

SleakOps descubre toda la topología de red de la cuenta una sola vez, al abrir el formulario (**Discovering network topology…**). Al seleccionar una VPC, los subnets, NAT Gateways e Internet Gateways que se muestran abajo se filtran a los de esa VPC.

## Asigná subnets a los slots

| **Setting**             | **Description**                                              |
| ------------------------ | --------------------------------------------------------------- |
| **Public subnets**        | Subnets con ruta hacia el Internet Gateway.                     |
| **Private subnets**       | Subnets que llegan a internet a través de un NAT Gateway.        |
| **Persistent subnets**    | Subnets para recursos con estado (bases de datos, storage).      |

Los tres slots son obligatorios — cada uno necesita al menos una subnet. Las descripciones de arriba son orientativas: SleakOps no verifica las rutas de las subnets. La misma subnet se puede asignar a más de un slot.

## Gateways

- **NAT Gateway(s)** — seleccioná al menos uno. Si la VPC no tiene ningún NAT Gateway, SleakOps muestra **This VPC has no NAT Gateways**.
- **Internet Gateway** — un único dropdown obligatorio. Si la VPC no tiene ninguno, SleakOps muestra **This VPC has no Internet Gateway attached**.

La Elastic IP de cada NAT Gateway se toma automáticamente de AWS — no hay un campo para elegirla por separado. Un NAT Gateway sin Elastic IP se marca con **This NAT Gateway has no Elastic IP attached**.

## Enviá e importá

**Save and apply** queda deshabilitado hasta completar los tres slots de subnets, al menos un NAT Gateway con Elastic IP y el Internet Gateway. Al enviarlo, la cuenta pasa a **Creating…** mientras SleakOps aplica la configuración — el panel cambia automáticamente al **network explorer** cuando termina.

El network explorer es una vista de solo lectura de la red importada: la VPC, sus route tables, el Internet Edge (Internet Gateway, NAT Gateway y su Elastic IP), y las subnets agrupadas en Public, Private y Persistent.

Desde acá, la cuenta está lista para importar su clúster.

## Proteger el balanceador público con un firewall de aplicaciones web

SleakOps puede poner AWS WAF delante del balanceador público de cada clúster, para frenar el tráfico malicioso antes de que llegue a tus aplicaciones. El firewall usa reglas administradas de AWS: reputación de IP, entradas maliciosas conocidas y el conjunto de reglas base. Viene desactivado por defecto.

Aplica a los clústeres creados por SleakOps (no a los importados) y solo al balanceador público.

### Activarlo

Solo los administradores pueden cambiarlo.

1. Abrí **Accounts & Networking** y seleccioná la cuenta.
2. Abrí **Web application firewall**.
3. Activá el firewall en el clúster que querés proteger.

El firewall arranca en modo **Count**: las solicitudes solo se cuentan y no se bloquea nada. Revisá las coincidencias durante aproximadamente una semana y después pasá el clúster a **Block**.

### Revisar falsos positivos

Antes de bloquear, mirá qué detectan las reglas:

- En tu cuenta de AWS, abrí la consola de **AWS WAF**, seleccioná la web ACL `sleakops-<cluster>` y revisá las métricas por regla y las solicitudes muestreadas.
- Si activaste el registro, los logs completos están en el grupo de CloudWatch Logs `aws-waf-logs-<cluster>`, con retención de 30 días. Los headers `Authorization` y `Cookie` se ocultan.

Una solicitud bloqueada recibe un `403` del balanceador. Si una regla puntual bloquea tráfico legítimo, dejala en **Count** desde el mismo formulario mientras las demás siguen bloqueando. Los cuerpos de solicitud de más de 8 KB nunca son bloqueados por la regla de tamaño de cuerpo.

### Grupos de reglas opcionales

Podés sumar otros grupos de reglas administradas de AWS, todos desactivados por defecto: IPs anónimas, inyección SQL y Linux.

### Costo

AWS cobra el firewall en tu cuenta, no SleakOps. Precios de referencia para us-east-1:

- USD 5 por mes por web ACL.
- USD 1 por mes por grupo de reglas (USD 8 por mes en total con los grupos por defecto).
- USD 0,60 por millón de solicitudes.

El registro suma cargos de CloudWatch Logs. Los precios varían según la región: consultá los [precios de AWS WAF](https://aws.amazon.com/waf/pricing/).

### Límites

- Un balanceador puede tener una sola web ACL. Si tu balanceador público ya tiene una web ACL que asociaste vos, SleakOps no la reemplaza y no activa el firewall.
- Si uno de tus propios Ingress del mismo ingress group define una annotation de AWS WAF, la tuya gana o el balanceador deja de actualizarse. Quitá esa annotation antes de activar el firewall.
- Si el balanceador no puede consultar a AWS WAF, AWS no reenvía la solicitud a tu aplicación (comportamiento por defecto de AWS), incluso en modo **Count**.

### Desactivarlo

Al desactivar el firewall se elimina la web ACL. Eliminar el clúster también la elimina.
