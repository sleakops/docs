Essential addons are the infrastructure glue every cluster needs to function under SleakOps: networking, DNS, autoscaling, and access control. Unlike the optional addons you pick from the Addons list, these six are always present — SleakOps installs them automatically on every managed cluster instead of waiting for you to add them. On a managed cluster created before CoreDNS became an essential addon, SleakOps installs it through the **CoreDNS Managed Addon** [upgrade](/docs/upgrades), which runs while the cluster is on. It keeps the cluster's DNS configuration (the Corefile), and the CoreDNS version when it runs the image AWS provides. Changes made by hand to CoreDNS outside its DNS configuration (for example its resources, tolerations or number of replicas) are replaced by the SleakOps settings; you can declare them again with Custom Values. The CoreDNS pods are replaced gradually and DNS keeps resolving while they restart. Until that upgrade runs, the cluster keeps the CoreDNS that AWS set up and the [System Resilience](/docs/cluster) setting has no effect on it.

They show in the Addons list like any other addon card, with no special badge or visual marker — you recognize them by name and description, not by a distinct treatment.

## The six essential addons

| Name | What it does |
|---|---|
| Metrics Server | Collects resource metrics from kubelets and exposes them through the Kubernetes Metrics API, enabling Horizontal Pod Autoscaling and `kubectl top`. |
| ExternalDNS | Synchronizes exposed Kubernetes Services and Ingresses with DNS providers (Route53), keeping cluster DNS records up to date automatically. |
| Karpenter | A Kubernetes node autoscaler that provisions right-sized compute capacity in response to unschedulable pods, improving efficiency and reducing cost. |
| AWS Auth | Wires SleakOps IAM roles into the cluster's `aws-auth` ConfigMap and the SleakOps RBAC ClusterRoles, enabling SleakOps integration and role-based access. |
| Load Balancer | The AWS Load Balancer Controller manages Application Load Balancers for Kubernetes Ingresses, plus the public and private IngressClasses used to route external traffic. |
| CoreDNS | The cluster DNS server that resolves internal Service names for every workload. SleakOps takes over the CoreDNS that AWS installs with the cluster and keeps its configuration (the Corefile, including stub domains and forwarders) and its version; its number of replicas and how they spread across nodes follow the cluster's [System Resilience](/docs/cluster) setting. You can override its configuration with Custom Values (see [Restrictions](#restrictions)). |

## Behavior on imported clusters

On a managed cluster, SleakOps installs and owns all six essential addons. On an imported cluster, SleakOps installs only **AWS Auth**, automatically, as part of the import; the other five behave differently:

| Addon | On an imported cluster |
|---|---|
| Metrics Server | Not installed automatically. Install it from the Addons list when you need it. |
| ExternalDNS | Not installed automatically. Install it from the Addons list when you need it. |
| Karpenter | Can't be installed: "Karpenter is not supported on imported clusters: node capacity is managed by the cluster owner." |
| Load Balancer | Can't be installed: "The Load Balancer addon is not supported on imported clusters: the ALB controller and its IngressClasses are managed by the cluster owner." SleakOps routes traffic through the IngressClass names set when the cluster was imported. |
| CoreDNS | Can't be installed: "The CoreDNS addon is not supported on imported clusters: CoreDNS is managed by the cluster owner." |

On an imported cluster, AWS Auth keeps every entry already in the cluster's `aws-auth` ConfigMap and adds the SleakOps roles to it.

## Restrictions

**Configuration** — an essential addon's configuration form is read-only on a managed cluster, since SleakOps owns that configuration. The exception is the **Enable Custom Values** switch of ExternalDNS and CoreDNS: turn it on to paste YAML that overrides the addon's configuration. For CoreDNS, the YAML takes the values the AWS-managed CoreDNS addon accepts for its installed version (for example `replicaCount`, `resources`, `tolerations` or `corefile`) and is applied over the replicas set by System Resilience; a list you set replaces SleakOps' list. A key the addon doesn't accept leaves CoreDNS in error with the message from AWS, and the CoreDNS already running keeps working. Custom Values are not managed by SleakOps: a SleakOps update may stop supporting them.

Load Balancer is the only essential addon with other configurable fields (its public and private IngressClass names), so it's the one where the read-only lock is visible:

**Deletion** — essential addons can't be deleted on a managed cluster ("'`<name>`' is an essential addon of this managed cluster and cannot be deleted."): they're only removed when the cluster itself is destroyed. On an imported cluster, they can be deleted like any other addon, unless another addon depends on them.
